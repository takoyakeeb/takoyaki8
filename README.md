# takoyaki8

takoyaki8 は、8キー(2行 × 4列)のマクロパッドです。
マイコンは RP2040-Zero で、ファームウェアは TinyGo(Go 言語)で書いています。
キーの割り当ては、専用の Web ツール(tinykeemap)から書き換えられます。

## 特徴

- 8キー(2行 × 4列)。スイッチは Choc v2 で、ホットスワップ式(ソケット: CPG135001S30)
- マイコン: Waveshare RP2040-Zero
- 0.91 インチ OLED(128 × 32、I2C)と、フルカラー LED(WS2812B-V5)4個を搭載
- ケース: トッププレート(メイン基板と同じパネルで製造)と、アクリル 2mm のボトムプレート・OLED カバー(光を通す透明なアクリル)
- キーマップは4レイヤー。レイヤー切り替え(MO / TG / TO)と、Shift などの修飾キー付きのキーに対応
- キーマップは本体の Flash に保存できる(書き換えには tinykeemap を使う)
- ファームウェアの設定は `config.go` にまとめてある

## 現在の状態

- 基板とアクリルが届き、組み立てと、動作の確認(キー入力、LED、OLED、tinykeemap での書き換えと保存)が済んでいます。ケースにも収まり、BOOT / RESET、USB、キーキャップとの干渉も、問題ありませんでした。
- 半日と、朝から夕方までの連続使用でも、熱くなったり、OLED が止まったりすることはなく、キーの取りこぼしもありませんでした。USB の抜き差しを10回以上繰り返しても、異常はありませんでした。3日間使っても、問題はありませんでした。
- ビルド済みのファーム(.uf2)は、まだ配布していません。
- 基板・ケースの設計データは、`hardware/` にあります。Gerber と部品表(BOM)は、準備中です。

## 基板・ケースの設計データ

設計データは、`hardware/` にあります。ライセンスは CERN-OHL-P-2.0 です(「ライセンス」の節と、`hardware/README.md` を参照)。

| 場所 | 内容 |
|---|---|
| `hardware/takoyaki8.kicad_pro`、`.kicad_sch`、`.kicad_pcb` | KiCad のプロジェクト、回路図、基板。KiCad 10.0 で作成しています(古い版の KiCad では、開けないことがあります) |
| `hardware/lib/` | 自作のシンボルとフットプリント。出典と、寸法の確認は、`hardware/lib/README.md` を見てください |
| `hardware/case/` | ケース(アクリル)の寸法メモ(`README.md`)、入稿用の図面(SVG)を作るスクリプト(`acrylic_svg.py`)とその検算(`check_acrylic_svg.py`)、配置データ(`layout_30x30_v2.json`)、ロゴなどの素材(`art/`) |

- 基板は、メイン基板とトッププレートを1枚のパネルにして、発注しました。マウスバイトで切り離します。KiCad の DRC には、マウスバイトの穴の警告が24件出ますが、意図した設計です。
- 発注に使った版には、タグ `hw-rev1.0-order1` が付いています。
- ケースのカバーには、C1 と C2 の2種類の図面があります。C1(右端が、基板の左端から 23.75mm)を使います。C2(24.5mm)は、幅 19mm のキーキャップに当たるので、使えません。
- 図面を作るスクリプトは、いまは、検証用に、複数セット分を並べた図面を作ります。1セット分の図面(SVG・PDF・DXF)は、準備中です。
- Gerber と部品表(BOM)は、準備中です。GitHub のリリースで配布する予定です。KiCad から Gerber を書き出す設定は、プロジェクトに保存してあります(出力先は `hardware/gerber/`。このフォルダは、リポジトリには含めていません)。

## 組み立て

メイン基板の組み立ては、次の順で行いました。低い部品から付けます。各段階のハンダ付けのあとに、通電する前に、テスターで短絡を確認します。

1. **準備**: パネルからメイン基板を切り離す。
   - パネルは、手で折って切り離せます。折ったあとに、2枚をつないでいた小さな突起が残るので、ラジオペンチで取り、ヤスリで整えます。
   - トッププレートは、あとで使います。
2. **基板の裏面(チップ部品)**: R1(0Ω)、C1〜C4(100nF)、D1〜D8、LED1〜LED4 の順に付ける。
   - ダイオードは、カソード(黒線側)が Row 側になる向きに付ける(COL2ROW)。付けたあとに、テスターのダイオードのモードで、順方向だけ導通する(目安 約0.5〜0.7V)ことを確認する。
   - LED は、1番ピン(欠けた角)と、シルクの▲を合わせる。静電気に弱いので、触れる前に、身体の静電気を逃がす。
   - LED を付けたあと、VCC(5V)と GND が短絡していないことを確認する。
3. **基板の裏面(ソケット)**: ホットスワップソケット CPG135001S30 を8個付ける。位置決めの突起を穴に入れ、基板に密着させて、ソケットの2か所の端子を、基板のパッドにハンダ付けする。
4. **基板の表面(RP2040-Zero)**: 部品面を下にして、基板の窓に部品を入れ、ハーフホールをハンダ付けする。USB-C は上辺側で、BOOT / RESET はボトムプレート側を向く。
   - 位置がずれやすいので、1か所を仮止めして、ハーフホールとパッドが全周で合っているか確認してから、すべてをハンダ付けする。マスキングテープなどで仮止めするとよい。
   - ハンダ付けのあと、5V(VBUS)と GND、3V3 と GND が短絡していないことを確認する。
5. **基板の表面(OLED)**: OLED 付属の 11mm のピンヘッダーを、OLED 側に最低限の飛び出し(約6.6mm)でハンダ付けし、OLED の裏にカプトンテープを貼る。RP2040-Zero の上に乗せて、基板側をハンダ付けする。ハンダ付けのあと、飛び出した余りのピンは、ニッパーで切り取る。浮き量は、実測で約2.95mm。OLED が傾かないこと、ガラスを強く押さないことに注意する。
6. **動作の確認**: ファームを書き込み、8キー、同時押し、LED、OLED、tinykeemap での書き換えを確認する(「ファームウェアの書き込み」「設定ツール tinykeemap」の節を参照)。
   - OLED の表示は、USB-C を右向きにして置くと読めます。OLED が縦置きに付くため、USB-C を上にすると、横倒しに見えます。向きは、今後変えるかもしれません。

ケースの組み立ては、基板の動作を確認したあとに、次の順で行いました。ケースの寸法は、`hardware/case/README.md` にあります。

1. **トッププレートにスイッチを付ける**: トッププレートに、スイッチを2個はめる。場所は、四隅のうち、対角の2か所。
2. **位置を決める**: 基板のホットスワップソケットに、トッププレートに付けたスイッチの端子を挿し込んで、位置を決める。
3. **残りのスイッチを挿す**: 残りの6個のスイッチを、ソケットに挿す。トッププレートが基板側に落ちないようにする。落ちていたら、持ち上げる(トッププレートと基板のすき間は、約 0.7mm)。
4. **トッププレート側のスペーサー**: トッププレートのネジ穴に、M2×4 のネジを通し、基板側から、スペーサー(5.5mm)を取り付ける(4か所)。
5. **ボトムプレートを付ける**: ボトムプレートのネジ穴に、基板側のスペーサーを合わせて乗せる。ボトムプレートのネジ穴から、M2×4 のネジで留める。
6. **カバー側のスペーサー**: OLED のある面から、基板のスペーサー用の穴に、12mm のスペーサーを、ボトムプレートのネジ穴に合わせて置く。ボトムプレートから、M2×6 のネジで留める(M2×4 でも可。3か所)。
7. **カバーを付ける**: OLED の上から、OLED カバー(アクリル)を置く。ネジ穴とスペーサーの位置を合わせて、M2×6 のネジで留める(M2×4 でも可。3か所)。カバーの窓が、OLED の表示領域に合うことを確認する。
8. **キーキャップを付ける**: キーキャップを付けて、カバーに当たらないことを確認する。カバーは C1 を使う。C2 は、幅 19mm のキーキャップに当たるので、使わない。

ボトムプレートとカバーの彫刻面は、基板側(内側)に向けます。ボトムプレートには、USB 側の切り欠き(深さ 3.0mm)と、BOOT / RESET を押す穴(φ3.0)があります。組み立てたあとに、BOOT / RESET が押せること、USB ケーブルが挿せることを確認します。

0603 のチップ部品、SOD-123 のダイオード、5050 の LED など、小さな SMD 部品があるので、ハンダ付けの難易度は高めです。

道具(目安): はんだごて(温度調整つき)、細いはんだ、フラックス、ピンセット、テスター、拡大鏡、ヤスリ、ラジオペンチ、ニッパー。

## ファームウェアの書き込み

ファームウェアは TinyGo で書かれています。ビルドと書き込みには、TinyGo が必要です(インストール方法は、TinyGo の公式サイトを参照してください)。

### ソースから書き込む

1. このリポジトリを取得して、フォルダに移動します。

   ```bash
   git clone https://github.com/takoyakeeb/takoyaki8.git
   cd takoyaki8
   ```

2. RP2040-Zero の **BOOT ボタンを押しながら**、USB ケーブルで PC につなぎます。
3. 次のコマンドで、ビルドと書き込みを行います。

   ```bash
   tinygo flash --target waveshare-rp2040-zero --size short .
   ```

書き込みはせずに、.uf2 ファイルだけを作りたいときは、次のコマンドです。

```bash
tinygo build -target=waveshare-rp2040-zero -o takoyaki8.uf2 .
```

### ビルド済みの .uf2 から書き込む(準備中)

ビルド済みの .uf2 は、まだ配布していません。配布するときの手順は、次のとおりです。

1. RP2040-Zero の BOOT ボタンを押しながら、USB ケーブルで PC につなぐ。
2. `RPI-RP2` という名前のドライブが現れる。
3. .uf2 ファイルを、そのドライブにコピーする。

### 補足

- 初期キーマップは、レイヤー0 が MacOS の操作、レイヤー1 が Google Meet(Mac 用)です。キーごとの割り当ては、`keymap.go` を見てください。
- `main.go` の `debug` を `true` にすると、キーのイベントがシリアルに出力されます。tinykeemap を使うときは、応答にデバッグの行が混ざるので、`false` のままにしてください。

## 設定ツール tinykeemap

キーマップは、Web ツール **tinykeemap** で書き換えられます。インストールは不要で、キーボードを USB でつないで、ブラウザで開くだけです。

- 公開ページ: <https://takoyakeeb.github.io/tinykeemap/>
- ソースコード・説明: <https://github.com/takoyakeeb/tinykeemap>

### できること

- キーボードに接続して、全レイヤーのキーマップを表示する
- キーを選んで、割り当てる keycode を変更する(変更はすぐに反映される)
- 変更をキーボードの Flash に保存する(SAVE)。保存した内容は、電源を切っても残る
- 保存済みの内容を読み直す(LOAD)、初期キーマップに戻す(RESET)

LED と OLED の設定は、まだできません。
対応しているキーの種類など、くわしくは tinykeemap の README を見てください。

### 使い方

1. キーボードを USB でつなぎます。シリアルポートを開くソフト(picocom など)を使っているときは、先に閉じます。
2. 公開ページを、Chrome または Edge で開きます。
3. 「接続する」を押して、表示された一覧からキーボードを選びます。
4. 変えたいキーを選び、割り当てる keycode を指定して、「変更する」を押します。
5. 気に入ったら、「保存する(SAVE)」を押します。保存するまでは、USB を抜き差しすると、保存済みの内容に戻ります。

### 注意

- 対応ブラウザは、WebSerial に対応した Chrome / Edge 系です。Firefox と Safari では動きません。
- SAVE は Flash に書き込みます。Flash は書き換え回数に限りがあるので、必要なときだけ保存してください。

## 配線とピン配置

ピン配置と配線表は、[docs/wiring.md](docs/wiring.md) にあります。

- マトリクス(COL2ROW): Row0 / Row1 = GPIO0 / GPIO1、Col0〜Col3 = GPIO2〜GPIO5
- LED のデータ線: GPIO26
- OLED(I2C): SDA = GPIO14、SCL = GPIO15
- ピンの定義は `config.go` にあります。配線を変えたときは、`docs/wiring.md` と `config.go` を同時に更新します。

`docs/wiring.md` には、配線表、ブレッドボードでの確認の記録、基板 rev1.0 の構成があります。

## ファイル構成

Go のファイルは、すべて `package main` で、リポジトリの直下に並んでいます。

| ファイル | 役割 |
|---|---|
| `main.go` | プログラムの入口。起動時に、LED、OLED を使える状態にし、Flash に有効なキーマップがあれば読み込む。メインループで、キーの読み取りと USB キーボードとしての送信、シリアルの処理、LED・OLED の更新を繰り返す |
| `config.go` | 設定をまとめたファイル。機種情報、ピン割り当て、行数・列数・レイヤー数、LED・OLED の設定。INFO コマンドの応答の元 |
| `scanner.go` | 入力元の共通の形(キーイベントと、スキャナのインターフェース) |
| `matrix.go` | COL2ROW のマトリクススキャナ。チャタリングの除去を含む |
| `keymap.go` | キーマップ(レイヤー × キー番号 = keycode)、初期キーマップ、有効なレイヤーからの keycode の検索 |
| `keycode.go` | keycode の定義。値は、tinykeemap の `docs/protocol.md` と同じ |
| `layer.go` | レイヤー切り替えキー(MO / TG / TO)の処理 |
| `mods.go` | 修飾キー(Shift など)を押す・離す処理。複数のキーが同じ修飾キーを押していても、正しく離す |
| `hid.go` | keycode を、TinyGo の USB キーボードの Keycode に変換する |
| `protocol.go` | tinykeemap との通信プロトコル(INFO / GET / SET / DUMP / SAVE / LOAD / RESET)の、コマンドの処理 |
| `serial.go` | USB シリアルから1行ずつコマンドを受け取り、応答を返す |
| `flash.go` | キーマップの Flash への保存と読み込み。保存先は、使える Flash 領域の最後の1セクタ。CRC32 で、内容が正しいかを確認する |
| `led.go` | LED(WS2812B)の制御。いまは、配線とコードの確認用の動き(白い点が動く)で、tinykeemap からは設定できない |
| `oled.go` | OLED(SSD1306、128 × 32、I2C)の表示。いまは、確認用の表示(「TAKOYAKI8」と、流れる印)で、tinykeemap からは設定できない |
| `go.mod`、`go.sum` | Go モジュールの定義と、依存するライブラリ(`tinygo.org/x/drivers`)の記録 |
| `docs/wiring.md` | 配線表とピン配置 |
| `hardware/` | 基板(KiCad)とケース(アクリル)の設計データ。中身は、「基板・ケースの設計データ」の節と、`hardware/README.md` を見てください |
| `LICENSE` | ソフトウェアと文書のライセンス(MIT) |
| `LICENSE-HARDWARE` | 設計データのライセンス(CERN-OHL-P-2.0) |
